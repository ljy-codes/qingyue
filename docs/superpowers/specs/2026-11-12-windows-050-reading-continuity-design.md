# 轻阅 Windows 0.5.0 设计方案

## 目标

0.5.0 定位为“连续阅读与文件组织”版本。

上一版已经解决了 Markdown 默认阅读、图文复制、阅读/编辑往返、外部文件刷新、浅色/深色主题和安装器流程。本版本不重复建设这些基础能力，继续围绕用户打开 Markdown/TXT 后的核心动作：持续阅读、定位、切换文件、回到上次位置。

本版本的可见结果是：

- 打开轻阅后能恢复上次的标签、活动文档、阅读/编辑状态和阅读位置。
- 文档阅读态显示当前阅读进度，并能用书签快速回到重要位置。
- 标签页可以直接右键完成常用操作。
- 最近文件路径失效时有明确提示和清理入口，不会看起来像“搜索不到”或打开后无反馈。
- 外部程序修改当前文件后，轻阅刷新最新内容，并尽量保持用户原来看到的段落、选区和阅读位置。
- Markdown 的目录、搜索、阅读/编辑切换继续保持当前滚动位置，不因状态刷新而跳回顶部。

## 范围

### 本版本包含

1. 阅读进度显示与保存
2. 书签模型、持久化、侧栏列表、跳转和删除
3. 标签页右键菜单和常用标签操作
4. 最近文件失效状态和快速清理
5. 外部更新后的阅读锚点映射增强
6. Markdown/TXT 阅读态的位置、搜索和目录回归
7. 0.5.0 版本号、测试、构建和本机安装交付

### 本版本暂不包含

- EPUB、PDF 或其他大型阅读格式
- AI 摘要、批注、云同步
- 多窗口协作
- 改造现有安装器页面和卸载流程
- 重做 Markdown 渲染器、剪贴板格式或主题系统

安装器继续沿用上一版已经验证的路径选择、单进度条、默认保留用户信息和完成后自动退出逻辑。除非构建回归发现版本号或产物命名问题，本版不扩大安装器修改范围。

## 用户可见行为

### 1. 阅读进度

阅读态工具条或状态区显示：

- 当前进度，例如“阅读进度 42%”
- 当前文档标题和保存状态
- 书签状态，例如“已标记”或书签按钮的选中样式

进度按当前源文阅读锚点计算。纯文本、代码和 Markdown 都使用源文位置，而不是 FlowDocument 的显示字符位置，因此 Markdown 标题、列表、图片和代码块的渲染差异不会导致进度跳变。

进度计算规则：

- 空文档显示 `0%`。
- 文档存在内容时按 `ViewportAnchor / 文本长度` 计算并限制在 `0%` 到 `100%`。
- 视口已经接近文档末尾时显示 `100%`。
- 编辑态仍显示行、列等编辑信息；阅读进度只在阅读态展示。
- 进度仅来自当前视口，不修改文件正文。

用户切换标签、退出阅读、关闭窗口或自动保存会话时，继续使用现有 `ViewportAnchor` 和 `ViewportDelta` 保存位置。0.5.0 不新增一套与现有会话恢复相冲突的进度字段。

### 2. 书签

阅读态增加“添加书签 / 删除书签”操作，快捷键为 `Ctrl+D`。书签保存：

- 文档路径或未命名文档的文档 ID
- 源文位置
- 创建或更新时间
- 自动生成的短标题，例如所在 Markdown 标题、所在段落首句或 `第 N 行`

书签跳转后：

- Markdown 跳到对应标题或内容块，并保留阅读视图顶部留白。
- TXT、代码和其他文本跳到对应源文行。
- 书签位置超过当前文件长度时自动限制到文件末尾。
- 书签删除只删除书签，不修改正文。

侧栏增加“书签”页：

- 按文档分组显示书签。
- 当前文档优先显示，其他文档按最近更新时间排序。
- 双击或按 Enter 跳转。
- 右键删除当前书签。
- 路径已经不存在的书签显示“文件不存在”，提供删除入口。

持久化使用独立的 `Bookmarks.json`，避免把长期书签混入会话恢复草稿。文件位于现有用户数据目录，采用临时文件加替换写入，限制大小和数量，读取失败时保留当前窗口功能并在诊断信息中记录警告。

书签的文档匹配规则：

- 已保存文件优先按规范化绝对路径匹配，大小写不敏感。
- 未保存文档按当前 `DocumentFile.Id` 匹配，只在该会话仍能恢复时有效。
- 文件另存为后，将原路径书签迁移到新路径，避免书签留在旧文件名下。
- 文件重命名后继续沿用当前标签对应的路径更新书签。

### 3. 标签页操作

标签页标题区域支持右键菜单：

- 关闭当前标签
- 关闭其他标签
- 关闭右侧标签
- 向左移动
- 向右移动
- 复制文件路径
- 在资源管理器中打开所在目录

已有菜单命令继续作为唯一业务入口，右键菜单只负责把目标标签传给现有命令，避免复制一套关闭、保存和会话持久化逻辑。

标签页保留当前的：

- `Ctrl+Tab` / `Ctrl+Shift+Tab`
- `Ctrl+1` 到 `Ctrl+9`
- 拖动左右排序
- 关闭时的未保存内容和恢复草稿处理

拖动标签时只改变标签顺序，不改变文档内容、阅读位置和书签。

### 4. 最近文件

最近文件列表对不存在的路径显示明确状态：

- 文件仍存在：正常显示文件名和目录。
- 文件不存在：显示“文件不存在”，降低文字对比度并提供移除入口。
- 路径无法访问：显示“暂时无法访问”，保留记录等待用户重试。

双击失效项时显示简短提示，不创建空标签、不覆盖当前文档。用户可以从右键菜单或“清除最近记录”移除失效项。

最近文件列表刷新时只做轻量 `File.Exists` / 目录可访问性检查，不读取正文，不阻塞窗口。打开操作继续由现有异步加载和取消机制负责。

### 5. 外部文件更新

现有行为继续保留：

- 切换到标签时检查当前文件。
- 窗口重新激活时检查当前文件。
- 无本地未保存编辑时自动接纳外部更新。
- 有本地未保存编辑时保留本地内容并提示冲突。

0.5.0 增强外部更新后的定位：

- 先根据旧正文和新正文计算源文位置映射。
- 如果用户位置前面插入或删除了完整行，阅读位置随原内容移动。
- 如果原位置所在段落仍能识别，优先按段落前后文恢复。
- 如果局部内容完全重写，退回到原位置附近的安全偏移，并限制到新文件范围。
- Markdown 重新渲染后继续恢复阅读选区、搜索选区、目录选中项和滚动位置。
- 不把外部更新产生的位移标记为用户编辑，不污染撤销栈和未保存状态。

外部更新期间保持现有异步、取消、版本检查和标签归属检查，旧读取任务不能覆盖新切换到的标签或新编辑内容。

### 6. Markdown 阅读连续性

本版本不改变 Markdown 默认全宽预览和复制行为，只补充连续性约束：

- 目录跳转后记录原位置，点击“返回位置”仍回到原视口。
- 搜索首次匹配、下一个/上一个匹配和关闭搜索后保留阅读位置。
- 编辑 Markdown 后重新进入预览，尽量按源文偏移恢复到原段落。
- 调整窗口、侧栏或阅读宽度时只更新现有文档版式，不把阅读位置重置到顶部。
- 图片异步加载完成后不改变当前源文锚点；图片失败只影响对应图片占位。
- 50 万字符上限继续沿用现有保护，不在本版本扩大渲染预算。

## 技术方案

### 状态和持久化

现有调用链继续作为主路径：

`TabChanged / Activated`
→ `QueueExternalRefresh`
→ `RefreshCurrent`
→ `CaptureReadingViewport`
→ `SchedulePersist`
→ `PersistWorkspaceAsync`
→ `WorkspaceStore.SaveAsync`

新增的阅读进度只从 `EditorTab.ViewportAnchor`、`ViewportDelta` 和正文长度计算，不改变 `WorkspaceEntry` 的兼容格式。

新增核心模型：

```csharp
public sealed record DocumentBookmark(
    Guid Id,
    Guid DocumentId,
    string? Path,
    int SourceAnchor,
    string Label,
    DateTimeOffset UpdatedAt);
```

新增 `BookmarkStore`，负责：

- 读取和校验 `Bookmarks.json`
- 按文档路径或文档 ID查询
- 添加、更新、删除和迁移书签
- 原子写入和失败回滚
- 数量、标签长度和文件大小限制

建议限制：

- 最多 500 个书签
- 单个标签最多 160 个字符
- `Bookmarks.json` 最大 1 MiB
- 任何异常不阻断主窗口，状态栏提示“书签保存失败，当前窗口仍可使用”

`MainWindow.Persistence.cs` 在窗口关闭、标签关闭、保存/另存为和书签变更后安排书签保存。读写仍在后台完成，UI 线程只捕获不可变快照。

### 书签定位

新增一个纯函数定位器，输入：

- 文档类型
- 文本
- 源文偏移
- Markdown 的 `ReadingModel`（如果有）

输出：

- 规范化源文偏移
- 显示标题
- 可选的 Markdown 显示偏移

Markdown 优先使用现有 `ReadingModel.Blocks` 和 `Headings`；普通文本使用行起始位置。定位器不直接操作 WPF 控件，便于在核心测试中覆盖空文档、末尾、标题、代码块和删除内容后的边界。

### 阅读进度刷新

滚动事件不直接写磁盘。使用现有视口捕获逻辑更新内存状态，并通过轻量 Dispatcher 防抖刷新 `ReadingStatus` 和 `StatusText`。真正的会话保存仍由现有持久化计时器完成。

进度刷新必须满足：

- 当前标签不变时只更新显示，不重建 Markdown 文档。
- 当前标签切换时先捕获旧标签，再恢复新标签的视口和进度。
- 阅读/编辑切换时使用同一个源文锚点。
- 外部刷新完成后以映射后的新锚点更新进度。

### 标签右键菜单

在 `MainWindow.xaml` 的 `TabControl.ItemContainerStyle` 或标签头模板上挂载上下文菜单。菜单命令的目标通过 `ContextMenu.Tag` 或绑定的 `EditorTab` 传递到统一处理函数。

关闭逻辑继续调用现有关闭入口，保证：

- 未保存内容仍按现有规则处理
- 恢复草稿不会被误删
- 关闭其他/右侧标签按当前顺序计算
- 关闭活动标签后正确选择相邻标签

“复制文件路径”和“在资源管理器中打开”只对已有路径启用；未命名草稿显示禁用状态。

### 最近文件状态

将 `RecentItem` 扩展为包含状态文本和可用性，而不是在 XAML 中临时判断文件系统。`RefreshRecent` 在后台检查路径，回到 UI 线程后按生成号更新列表，避免用户快速清理或打开时旧结果覆盖新结果。

打开失败沿用 `OpenPathsAsync` 的异常提示；最近列表只增加状态与移除操作，不改变打开流程。

### 外部更新位置映射

在 `Qingyue.Core` 增加无 UI 的 `TextAnchorMapper`：

1. 对旧正文和新正文计算共同前缀、共同后缀。
2. 对锚点附近按行和段落建立小窗口。
3. 优先匹配锚点所在行的稳定前后文。
4. 如果匹配成功，将旧锚点映射到新内容对应位置。
5. 匹配失败时根据共同前缀/后缀进行保守偏移。
6. 所有结果都限制在新正文长度内。

`MainWindow.ExternalChanges.ApplyExternalRefresh` 在 `TryApply` 前保存旧正文、阅读起止源偏移和编辑选区，接纳成功后用映射器转换，再调用现有 `EnterReading`、`RestoreReadingViewport` 和编辑器选区恢复。映射器不负责判断冲突，冲突判断继续由 `ExternalFileRefresh` 和 `DocumentFile` 完成。

## 兼容性和数据安全

- 旧版 `Session.json`、草稿和 `Settings.json` 可以继续读取。
- `Bookmarks.json` 不存在时按空书签处理。
- `Bookmarks.json` 损坏时隔离为备份文件，保留当前文档和旧会话，不让主窗口启动失败。
- 书签文件只保存路径、位置和短标签，不复制正文或图片。
- 关闭标签时默认只删除内存标签；书签保留，除非用户在书签侧栏明确删除。
- 删除最近文件只删除最近记录，不删除磁盘文件。
- 外部文件更新不改变用户未保存内容；冲突仍需要用户明确处理。
- 复制路径和打开资源管理器使用系统 API，路径不存在时给出状态提示，不创建新文件。

## 验收标准

1. 重启轻阅后，之前的标签顺序、活动标签、阅读/编辑状态和阅读位置恢复。
2. 阅读态可以看到 `0%` 到 `100%` 的进度，切换标签和滚动后显示与当前文档一致。
3. `Ctrl+D` 可以在当前阅读位置添加/删除书签，重启后书签仍在。
4. Markdown 书签跳转到对应标题或段落，普通 TXT 书签跳到对应行。
5. 另存为或重命名后，原书签迁移到新路径，不出现重复书签。
6. 标签右键菜单可以完成关闭当前、关闭其他、关闭右侧、左右移动、复制路径和打开目录。
7. 最近文件不存在时有明确视觉状态，双击不会创建空标签，用户可以移除记录。
8. 外部文件在锚点前插入或删除内容后，阅读视图仍尽量停留在原来的段落；旧任务不能覆盖当前标签。
9. Markdown 目录、搜索、编辑/预览往返、窗口缩放和图片异步加载的既有行为继续通过回归测试。
10. 0.5.0 Windows 构建、安装器和本机安装验证完成，工作区干净并推送到 `feat/windows-client`。

## 风险与控制

- 书签长期保存依赖路径；文件被移动到轻阅之外的位置时无法可靠追踪，界面显示失效并允许删除。
- 外部更新的文本映射属于启发式定位；无法确认原段落时只做保守偏移，不假装精确恢复。
- 频繁滚动可能触发过多 UI 更新；使用 Dispatcher 防抖，禁止每次滚动都写磁盘或重建阅读文档。
- 标签右键菜单可能与现有拖动、双击和关闭按钮事件冲突；先补充 WPF 交互测试，再做最小模板改动。
- 书签文件写入失败不能影响正常阅读和编辑；保存错误进入状态栏和诊断信息，下一次变更继续重试。
- 新增数据文件和版本号必须保持旧版本可读，发布前执行恢复、外部刷新、Markdown 和安装器完整回归。

## 设计自检

- 已围绕现有调用链和核心类型定位修改范围，没有重复实现已有的会话恢复、最近文件、快速打开和外部刷新基础流程。
- 书签、进度、标签操作、失效路径和外部更新定位都能落到现有 `EditorTab`、`WorkspaceStore`、`MainWindow` 和测试项目中。
