## 实施边界

Windows 需要在 Windows 环境中单独处理。本文原始版本是需求和验证记录；
当时没有 Windows 客户端。当前实现状态以本文顶部更新及独立验收为准。

用户要求保留轻量、本机、文本读写的定位，格式以 TXT、Markdown、JSON/JSONC、YAML、INI/CONF/CONFIG 等为主，不扩展为 Office 工具、完整 IDE 或电子书管理系统。

Mac 与 Windows 的信息统一记录到 GitHub；各平台客户端、构建、安装和实机验收分别维护。产品版本可以保持 0.1.0，平台构建编号和产物名称应能独立区分。Mac 的 AppKit 界面、CFBundleVersion 和 Darwin 文件操作不能直接作为 Windows 对应实现。

## 可以复用的内容

优先复用行为约定和测试样例，再评估是否共享某些算法代码：

- 编码识别、BOM、换行保持与显式转换规则。
- JSON 数字原始写法、JSONC 注释检查、YAML 校验程度的说明。
- Unicode 范围单位、中文/Emoji/组合字符、零宽匹配与捕获替换语义。
- 源文范围和阅读显示范围的块级对应规则。
- 文档修改状态、撤销、保存、冲突、恢复草稿的生命周期。
- 用户主动保存原文件，恢复草稿与标签会话分别管理。

当前 `TextSearch` 与 `TextEditing` 可作为行为样例，是否直接移植其 Foundation 实现须在 Windows 工具链验证。先不要为跨平台目标重写已可用的 Mac 客户端，也不预先指定 Windows 的界面框架、共享语言或 FFI 方案。

## Windows 必须独立验证的部分

| 能力 | 要核对的差异 |
| --- | --- |
| 文件打开与路径 | 中文文件名、长路径、大小写规则、重命名、重复打开同一文件 |
| 文件保存 | Windows 原子替换能力、文件被占用、只读属性、ACL、磁盘写入失败 |
| 链接 | 符号链接、硬链接与权限，不能照搬 Mac 的 POSIX/ACL 分支 |
| 文本编辑 | 中文输入法组合输入、候选时的 Enter/Tab/Esc、剪贴板、撤销与重做 |
| 阅读 | 字体回退、缩放、表格、版心和锚点恢复；不能只做静态截图验收 |
| 搜索 | 正则方言、全词边界、Unicode 偏移、零宽匹配、超时与取消 |
| 窗口与快捷键 | Windows 的关闭/退出习惯、Ctrl 系列快捷键、键盘和无障碍访问 |
| 安装与升级 | 独立安装包、签名、文件关联、旧版本替换与用户数据保持 |
| 资源 | 在 Windows 设备上独立测启动、输入、搜索、恢复写入、峰值和回收 |

## 建议的第一个 Windows 验证闭环

1. 打开带中文与 Emoji 的 UTF-8/BOM、UTF-16 和 GB18030 样例。
2. 编辑、保存、另存为，逐字节核对编码、换行和数值。
3. 在两个标签间切换并分别撤销，确认不会串文档。
4. 阅读中查找和跳目录，保持阅读视图；切回源文落在对应内容块。
5. 处理外部修改、被占用、权限不足和恢复失败，保持当前编辑内容。
6. 记录本机资源与输入延迟，再据结果决定技术方案和后续范围。

现阶段不以“能在 Mac 上交叉编译”或“共享了若干文件”代替 Windows 实机验证。Windows 的实现、测试结果和已知限制应在其独立工作完成后补入此文档及发布记录。
