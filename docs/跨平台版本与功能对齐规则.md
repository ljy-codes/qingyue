# 轻阅 GitHub 分支、版本与功能对齐规则

参考 [api-workbench 的分支与发布约定](https://github.com/ljy-codes/api-workbench)。轻阅采用 Swift/AppKit 和 C#/WPF 两套原生实现，功能契约统一。

## 长期分支

| 分支 | 职责 | 本次整理 |
|---|---|---|
| `main` | 项目基线、公共约定、功能矩阵和说明 | 合入当前 Mac 交付及约定；Windows 源文件维持既有内容 |
| `macos` | Mac 原生实现、系统适配和发布验收 | Mac 0.4.0 / 构建 14 |
| `windows` | Windows 原生实现、安装器和发布验收 | 直接承接原 `feat/windows-client` 的 `0869803047bbff82a1c38b1bf61ee1fe53a3e60e`，不改代码 |

临时 `codex/*`、旧 `feat/*` 分支在对应长期分支接续并核对提交后删除。Git 提交历史保留，可追溯历史实现。

## 版本与标签

- Mac 产品版本的次版本号使用偶数：0.4.0、0.6.0……；构建号也使用偶数：14、16……。
- Windows 后续产品版本的次版本号使用奇数：0.19.0、0.21.0……；历史 0.18.0 不重新编号。
- 新标签使用 `v<X.Y.Z>-macos` 或 `v<X.Y.Z>-windows`；本轮 Mac 标签是 `v0.4.0-macos`。
- 每个平台只保留最新 Release 和标签；旧版本经提交历史追溯。
- Windows 本轮未重新验证，保留其既有 Release/tag/安装包；后续 Windows 工作先确认现状，再执行奇数版本和单最新版本规则。

## 功能对齐

两端最终应达到同一功能契约，详见[功能对照表](功能对照表.md)。新增功能必须同步记录两端实现与各自测试结果。阅读、编辑、搜索、Markdown、图片、表格、Mermaid、工作区、阅读清单、书签、批注、恢复和导出属于共同能力。

系统菜单、快捷键、文本组件、剪贴板、文件对话框、签名和安装器允许使用平台原生实现。不能以一端的自动测试或截图代替另一端实机验收，也不能把“目标一致”写成“当前已经全部一致”。

## 当前交付边界

Mac 0.4.0 为预览版：本机 Intel 回归及 universal 构建已检查，Apple Silicon 实机、Developer ID、公证和多屏验证仍待完成。Windows 沿用历史 0.18.0，本轮只调整分支入口名称。
