# Qingyue 0.9.0 Update Entry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users check the latest stable GitHub Release without blocking startup or changing existing session/bookmark data.

**Architecture:** Add a small Core-independent update service in the WPF project. It reads the latest release metadata, compares stable semantic versions, and returns a value object. The window exposes a manual check command and a throttled startup check through existing status/notification UI; downloads open the verified Release page in the system browser.

**Tech Stack:** .NET 10, `HttpClient`, `System.Text.Json`, WPF, GitHub Releases API.

**Spec:** `docs/superpowers/specs/2026-11-16-qingyue-release-roadmap-design.md`

## Global Constraints

- Startup checks must be cancellable and have a short timeout.
- Network failures must never prevent the main window from opening.
- Only stable versions are eligible.
- Existing JSON settings, workspace and bookmark files remain compatible.

### Task 2: Implement the update service

**Files:**
- Modify: `开发空间/Windows/src/Qingyue.Windows/UpdateService.cs`

- [ ] **Step 1: Define the result and injected transport**

Use a record containing `IsAvailable`, `CurrentVersion`, `LatestVersion`, `ReleaseUrl`, `PublishedAt` and `Error`. Accept an `HttpClient` and an API URI in the constructor.

- [ ] **Step 2: Implement bounded HTTP and stable release parsing**

Use a 5-second cancellation timeout, an explicit `User-Agent`, `GetStringAsync`, and `JsonDocument`. Ignore drafts and prereleases; parse tags after an optional leading `v`; require a valid installer or release page URL.

- [ ] **Step 3: Run the focused tests green**

Run the UI test project and verify all update checks pass.
