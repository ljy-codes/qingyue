## 建议中仍值得处理的事项

独立只读审查使用当前源码和 7/7 合成断言确认以下风险；通过代表风险复现及对照成立，**不代表已修复**。
证据位于 ignored `开发空间/Windows/artifacts/persistence-audit-20261110`，使用无 GUI 桩，未接触真实草稿。

| 优先级 | 当前 Windows 结论 | 最小处理方向 |
| --- | --- | --- |
| P1 | 关闭恢复会话但开启草稿时，初始化跳过旧草稿加载，空会话自动保存可以清理旧草稿 | 分离会话重开与草稿恢复；未加载、未明确放弃的草稿不得清理 |
| P1 | 退出等待持久化期间仍可修改正文，保存快照后的输入可以未入恢复记录便关闭 | 退出确认后冻结编辑并在失败时还原，或关闭前复核版本并重新保存；尚未验证真实键盘/IME |
| P1 | 脏文件改名后，草稿已提交而会话尚未提交的中断状态会导致路径不匹配，正文被隔离而不自动恢复 | 提交代次或匹配备份；无法确认路径时恢复为无路径副本；普通可捕获异常的回滚对照已通过，未实际模拟断电 |
| P2 | 改名不迁移路径排除列表，重新打开新路径后可重新生成原本排除的草稿；标签级关闭标记仍有效 | 改名成功后迁移排除路径，失败改名不改变设置 |
| P2 | 保存的是选区/光标，纯滚动不会更新源文锚点，因此无法凭当前会话字段恢复阅读视口 | 防抖保存视口顶部源文锚点；实际 WPF 恢复效果仍需验证 |

当前优先级：含图 MD 实际卡死 → 草稿与退出保护 → 阅读位置连续性 → 大文件搜索的分块与取消。
Windows 已有的默认预览、搜索高亮、50 万正文、图片预算、格式化、标签排序及外部更新无需照旧报告重复实现。
文件夹搜索、导出等扩展后置；暂不扩大到完整代码编辑器、EPUB 或框架重写。
