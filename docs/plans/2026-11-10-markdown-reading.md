# Windows 构建 4：Markdown 阅读与文件同步

## 已确认事实

- 基线为 feat/windows-client / e3eb393；开始时工作区干净。
- 基线第二次启动直接退出，没有文件路径转发。
- 基线 Markdown 分屏和阅读正文上限均为 20 万，图片只显示占位文字。
- 基线搜索完成后仅计数；选中匹配需要再次操作。
- 基线切换文件不检查磁盘变动，保存时已有摘要冲突检查。

## 本轮方案

1. 使用资料目录隔离的单实例通信，第二进程转发打开路径，现有窗口接收并激活。
2. 磁盘 Markdown 默认全宽富文本预览，返回编辑才显示代码，保留显式分屏功能。
3. 图片在原生 WPF 中异步解码：相对路径基于文档位置，支持中文/空格和内嵌 data 图片；失败显示原因，原文不变。
4. 正文富预览提高到 500,000 字符。Markdown 内嵌图片的 Base64 负载不计入正文，仍受文件 50 MiB 与解码资源上限约束。超限明确降级原文。
5. 搜索自动定位并高亮当前匹配，不抢搜索输入焦点，不修改原文和撤销栈。
6. 切换标签及窗口激活时异步检查磁盘，干净文档自动刷新，未保存文档保留编辑并提示冲突。

## 范围与兼容

- 只改 Windows。保留 Mermaid、会话、编码、原子保存和磁盘冲突保护。
- 已恢复会话保留用户上次选择的编辑/阅读状态；首次打开磁盘 Markdown 使用预览。
- 不请求网络图片，不引入 WebView 或第三方 NuGet。
- 并行写集：启动 IPC、图片渲染、外部同步独立；主控负责预览/搜索/集成及发布。

## 风险

- 富文本布局及图片解码须避免大量数据在 UI 同步阻塞。
- 富文本搜索映射不能依靠更改 Run 文本或拆分 Run 来添加高亮。
- 自动刷新不能覆盖检测开始后新产生的本地编辑。
