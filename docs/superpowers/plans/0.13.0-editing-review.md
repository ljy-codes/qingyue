## 原始审查证据

审查范围：[MarkdownEditing.cs](D:/专用工具/阅读器/qingyue/开发空间/Windows/src/Qingyue.Core/MarkdownEditing.cs)。源码快照 SHA256：`6E05CE180A2D1E7950898AAF686F040FD522C5635FBFADD1E66E21E0F7BAB0CE`，复核期间未变化。以下行号对应此快照；未比较历史实现，无法判断各问题首次引入时间。

1. **[P2] lazy 续行提前截断后代扫描，导致子项改变父级。**

   位置：`ChangeIndent`，第 174–178 行。

   ```csharp
   text = "- a\n- b\nlazy\n  - c";
   Apply(text, text.IndexOf("- b"), 0, MarkdownEditAction.Indent);
   ```

   实际输出：

   ```text
   - a
     - b
   lazy
     - c
   ```

   `ListMarkers` 在该输入中保留 lazy 列表上下文，但移动子树时遇到零缩进 `lazy` 即停止，`c` 没有随 `b` 移动。操作后 `b` 和 `c` 都是 Level 1，原来属于 `b` 的 `c` 变成其同级项。应携带续行及其后的完整后代，不能单凭该行缩进判断列表子树结束。

2. **[P2] 正文列仍与源码字符偏移混用，Tab 会造成错误缩进和父项归属。**

   位置：第 162–164 行的降级宽度计算、第 223 行的 `FindOwner` 判断，以及第 89–98 行的续段缩进。

   ```csharp
   text = "-\tparent\n- child";
   Apply(text, text.IndexOf("- child"), 0, MarkdownEditAction.Indent);
   ```

   实际只给 `child` 增加 2 个空格；按文件采用的四列 Tab 规则，首项正文起始列为 4，应增加 4 列。

   另一个父项误归属输入：

   ```csharp
   text = "- parent\n\t- child\n\n    parent continuation";
   Apply(text, text.Length, 0, MarkdownEditAction.Enter);
   ```

   实际插入 `"\n\t- "`，继续了子级列表。空行后的四空格续段达不到子项正文列 6，应归属顶层 `parent`，插入 `"\n- "`。当前判断把 `"\t- "` 的 3 个字符当成 3 列，错误选择了子项。建议统一计算正文显示列；保留现有 UTF-16 source offsets。

3. **[P2] 任务框被计入容器缩进，标准两空格任务续段无法找到父项。**

   位置：第 223 行，以及第 88–91 行。

   ```csharp
   text = "- [ ] task\n\n  continuation";
   Apply(text, text.Length, 0, MarkdownEditAction.Enter);
   ```

   实际返回 `null`。`ContentStart - Start` 为 6，`FindOwner` 因续段只有两列而拒绝归属；应识别为任务项续段，并生成同级任务前缀。`ChangeIndent` 已扣除任务框的 4 个字符，续段归属也需要一致的容器缩进规则。仅修改 `FindOwner` 仍不足，第 89 行的重复判断也需同步。

4. **[P2] 批量格式保护遗漏列表内部的缩进代码，会改写代码内容。**

   位置：`BlockPrefix`，第 248–251 行；相关入口判断为第 77–79 行。

   ```csharp
   text = "- item\n\n      code\n- next";
   Apply(text, 0, text.Length, MarkdownEditAction.Heading1);
   ```

   实际输出：

   ```text
   # - item

         # code
   # - next
   ```

   原先六空格的 `code` 行是列表容器内再缩进四列的代码。它能找到列表 owner，因而绕过独立缩进代码保护，被插入 `# `。应结合容器正文列及块边界识别列表内缩进代码；结构升降层可以携带代码，批量标题等格式命令应保留代码内容。
