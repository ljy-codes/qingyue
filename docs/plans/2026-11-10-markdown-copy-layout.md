# Windows 构建 5：Markdown 往返、复制与缩放

## 已确认事实

- 基线为 `feat/windows-client / e3b527d`，开始时工作区干净。
- 用户明确说明：同一 MD 在轻阅中打开并复制到其他地方，格式混乱；腾讯文档打开后复制正常。因此本轮检查出站复制，不做入站粘贴转换。
- 调用链为工具栏 `MenuAction → ExecuteAction → ToggleReading → EnterReading → RefreshCurrent`；渲染为 `MarkdownPreview → RenderedReading → RichDocumentMap`。
- 预览使用 WPF RichTextBox，编辑使用 TextBox；搜索框拥有独立焦点范围和命令边界，必须保留。
- 仅修改 Windows 及说明。无 SQL、缓存、MQ、事务或外部服务变更。

## 当前方案

1. 增加真实按钮事件的多轮预览/编辑切换回归，分别覆盖不修改和修改后返回、分屏以及标签切换。先复现再修复状态与呈现不一致。
2. 调查 Markdown 阅读预览复制的实际数据格式，使用合成标题、表格、图片验证选择范围与富文本结构。保留纯文本及原有格式，向兼容 HTML 的接收方提供结构化内容；编辑源码和查询输入框复制维持原行为。
3. 调查真实主窗口宽窄变化后的文档、表格、图片布局。避免修改原文、重建选区和丢失滚动/搜索状态。
4. 完成统一回归和独立复核，升级至 0.2.0.5，打包、本机原位更新、隔离桌面验收并推送。
